# Port of Duqm e-Services Security Compliance Report

Assessment date: 3 August 2026  
Application: CodeIgniter 4 `port_of_duqum` admin and e-services application  
Excluded: WordPress website controls except where the same requirement has a direct PHP application equivalent

## Executive decision

The application now contains substantial security controls for authentication, sessions, role and company scoping, vendor CR isolation, protected documents, workflow integrity, payment verification, QR scanning, notifications, logging, and server exposure. This is an **application-code assessment**, not a production accreditation.

**Production go-live is not approved by this report.** The remaining gates include production secrets for enabled services, migration execution and schema reconciliation, Git-history and credential remediation, infrastructure encryption, TLS/WAF/server verification, backup restoration, malware scanner activation, historical Google Drive permission cleanup, an independent security test and retest, training, and formal PODC sign-off. Payment and SMS are deferred for the current release; they must remain disabled and require separate activation evidence and PODC acceptance before being marked Done.

**Framework/runtime status:** the bundled framework now reports CodeIgniter 4.7.4, and `tests/FrameworkRuntimeVersionTest.php` verifies that security baseline. The restored root `spark` entry point boots the root-layout application, and both `spark` and `index.php` reject PHP below 8.2 (`tests/CliMigrationEntryPointTest.php`). `tests/FrameworkConfigCompatibilityTest.php` also regression-protects the merged CodeIgniter 4.7 configuration, including CLI-safe `App`/`Rise` bootstrap, JSON encoding depth, migration locking and the other required compatibility properties. This closes the source-bundle upgrade blocker, but it is not production approval: the release artifact must still pass full compatibility, SBOM/SCA and security regression testing on a fully patched production PHP runtime; PHP 8.3 or 8.4 remains the deployment recommendation. See the [official CodeIgniter 4.7.4 security changelog](https://codeigniter.com/user_guide/changelogs/v4.7.4.html), [4.6.x to 4.7 upgrade guide](https://codeigniter.com/user_guide/installation/upgrade_470.html), and [PHP supported-version table](https://www.php.net/supported-versions.php).

**Dependency assurance snapshot:** a read-only inventory found eight independent top-level Composer lockfiles containing 53 production package entries, zero `packages-dev` entries and zero lock-embedded abandoned flags. This is inventory evidence, not a vulnerability-clear result. A live `composer audit` could not run because approved advisory-network egress was unavailable and no cached advisory database existed. PHP-Hooks, Paytm, php-duration-master, recaptcha and tcpdf have no lockfile/SBOM coverage and remain explicit pre-production inventory and SCA work.

## Evidence pack required for final acceptance

The checklist should be marked complete only when the release evidence folder contains, at minimum:

1. The exact release commit and clean build manifest.
2. Migration output, schema version, reconciliation queries and protected-file checksums.
3. Secret/credential rotation record without secret values.
4. Approved role/company/CR authority matrix and negative authorization test results.
5. TLS, security-header, source-disclosure, directory, port and WAF scan results.
6. reCAPTCHA and enabled-webhook end-to-end evidence; written PODC acceptance that SMS and payment are deferred, followed by separate iBulk/payment evidence before their later activation.
7. Malware scanner activation and safe detection test.
8. Database/volume/object-store encryption and least-privilege evidence.
9. Backup success plus full restore-drill report.
10. SIEM/monitoring dashboards and alert-response test.
11. Unified SBOM covering lockfile and no-lock components, current per-lock Composer/advisory results, SAST/SCA/secret scan, authenticated DAST, penetration report, remediation and retest.
12. Signed supplier security-accountability, warranty, support and incident-response obligations.
13. Training attendance, accepted residual exceptions and formal go-live signatures.
