# Port of Duqm e-Services Residual Security Risk Register

Assessment date: 3 August 2026  
Scope: CodeIgniter 4 `port_of_duqum` application and its production dependencies; WordPress is excluded.

This register contains **only risks that remain after the application hardening work**. Earlier findings that are now represented by implemented controls are documented in `SECURITY_COMPLIANCE_REPORT.md` and are not repeated here. Application implementation is not production acceptance: deployment, provider, organizational and independent assurance gates remain open.

## Rating and closure rule

- **Critical:** production blocker with plausible severe compromise, data disclosure/corruption, or invalid security assurance.
- **High:** production blocker unless PODC security formally accepts a time-bound exception and compensating controls.
- **Medium:** remediate on an agreed plan before or shortly after launch only with documented ownership and monitoring.
- A risk closes only with evidence, retest and owner approval. A code commit or configuration statement alone is not closure.

## Accepted application controls to preserve

The following controls should be regression protected during residual-risk treatment:

- Production HTTPS/cookie/session fail-closed configuration and canonical de-duplicated dynamic security headers.
- Persistent lockout, generic login/reset responses, strong password policy, atomic fail-closed session-version revocation, and vendor password limiting before credential verification.
- Provider-backed, expiring, retry-limited MFA with keyed OTP storage.
- Vendor email/password login followed by authorized CR selection and per-request CR revalidation; active Vendor, Gate Pass and PTW memberships resolve independently, role-less identities with no active membership lose stale sessions, and authenticated external identities cannot escape through `parent(false)` controller subclasses.
- Credential emails omit reusable passwords and provide only the approved non-secret notice/instructions.
- OWNER/EDITOR/BIDDER/VIEWER authorization plus company/assignment-scoped Gate Pass, Tender and PTW access.
- Global CSRF and denial of state-changing GET requests.
- Strict same-origin post-login redirects matching scheme, host and effective port, with userinfo and CR/LF rejection.
- Contextual file allowlists, MIME/magic/size checks, protected storage, randomized names and canonical containment.
- Payment amount/currency canonicalization, signed/idempotent callback processing and atomic single-use settlement.
- Tender paid-download window, staged technical/commercial separation and protected three-role opening secrets.
- Unique QR tokens, one-time scan proofs and transactional replay controls.
- Signed/replay-resistant integrations, allowlisted and TLS-verified Slack/Pusher delivery, private Google Drive streaming, object-instantiation-disabled legacy deserialization, CSV formula neutralization and secret-redacting logs.
- Bundled CodeIgniter 4.7.4, the merged-framework configuration compatibility contract, and root-layout web/CLI entry points enforcing PHP 8.2 as the minimum application floor.

Any rollback or vendor update that weakens these controls requires a new security review and explicit PODC approval.
