Scope: the supplied log and screenshots from e-svc.portofduqm.om.
Changes were prepared and tested locally. The destination server has NOT been
changed by this repair. Keep its current .env, Database.php and .htaccess.

1. GATE PASS LIST, SAVE AND CSV ERRORS

The supplied log contains 22 instances of:
  Incorrect TIMESTAMP value: '0000-00-00 00:00:00'
All originate in Gate_pass_requests_model::get_details(), called by the list,
save response and CSV export. The ordering query compared TIMESTAMP columns
with an invalid date literal. It now compares their text representations while
preserving date ordering, legacy zero-date fallback and request access filters.
No SQL-mode relaxation or database data rewrite is required.

The save now prepares its response before committing. It preserves SQL NULL for
optional department/submission dates and supplies a provisional unique reference
before replacing it with the final GP-year-ID reference inside the transaction.
This also supports strict schemas requiring reference on the initial insert.

Some earlier save attempts may ALREADY have committed before the list lookup
failed. After deploying, inspect My Requests for duplicate drafts before creating
another request. Nothing in this patch deletes existing requests.

2. LANGUAGE SWITCHER (ENGLISH / ARABIC)

The old topbar deliberately hid language selection from external portal users.
The switch is now available for Vendor, Gate Pass and PTW portal identities
unless the administrator explicitly hid the language menu in topbar settings.
It uses a dedicated authenticated POST endpoint that only changes the signed-in
user's language and accepts installed language names. Internal staff controllers
remain inaccessible to portal-only users.

The missing Arabic default_lang.php is included: it configures Arabic/RTL and
the bundled ar-AR editor locale, with English fallback for untranslated keys.
Arabic desktop, collapsed-sidebar and mobile shell offsets now match the current
sidebar widths, preventing content overlap.
This selects the application's translations; it is not a machine-translation
service for user-entered company names or documents.

3. PTW APPLICATIONS - AVAILABLE TO REGISTERED USERS

Updated to the confirmed requirement: signed-in registered applicants can open
PTW Portal / My PTW Applications and New PTW without an applicant-company
assignment. This includes Vendor and Gate Pass users, and regular staff/client
accounts. Existing disabled-account, revoked-login and accounting-only-role
restrictions remain intact; this change does not reactivate blocked logins.

Applicants select the receiving company from existing non-deleted companies.
They can create drafts, submit and view their own applications, revise when
returned by a reviewer, access their own attachments and download completed
approved permits. Company selection grants no access to other users' records.
The company on an existing application remains immutable.

PTW Master, reviewer inboxes and approval permissions are unchanged. Reviewers
still need an active assignment to the application's company. No applicant
assignment or SQL/data migration is required for this access change.

The draft-save path also preserves SQL NULL for optional coordinates and dates;
the common text sanitizer previously converted these to invalid empty strings.

Both files below are newly included in this revised patch:
  app/Controllers/Ptw_portal.php
  app/Libraries/Left_menu.php

4. VENDOR REGISTRATION: AUTHENTICATION FAILED

The screenshot alone cannot distinguish an incorrect password from an inactive
or disabled existing account. The supplied log has no vendor exception.
The registration uses the Account access/login email to identify an existing
account. If that email already has Gate Pass, PTW or Vendor access, enter its
CURRENT sign-in password. A new/different password is not allowed to overwrite
an existing account during public registration.

The form now explains this, shows a useful error beside the password field,
and focuses that field. Password verification and disabled-account protection
are retained. If the current password is unknown, an administrator must check
the account and reset it through the existing account management process.
SMTP password-reset delivery has not been tested and is not required for this
repair. No user's password was changed.

5. BROKEN SIDEBAR LOGO

If the configured uploaded logo cannot load, the sidebar now falls back once to
assets/images/port-duqum-signin-logo.png. This prevents a broken-image icon but
does not repair permission/missing-file problems affecting other uploads.
To restore a custom logo, check its file URL or upload it again in settings.
